Problem Statement

Industry Pain Points & Current Limitations

1. Fragmented Cloud Visibility

  • Engineers lack a single unified view across AWS accounts and regions.
  • AWS CloudWatch dashboards require manual setup and lack contextual correlation.

2. Critical Security Misconfigurations

  • Over 80% of data breaches stem from simple misconfigurations.
  • Exposed SSH (22) and RDP (3389) open to 0.0.0.0/0 on the public internet.

3. The Idle Energy Paradox

  • Idle servers draw up to 40% base electricity without performing productive work.
  • Existing tools fail to provide continuous carbon and energy modeling.

4. Credential Sprawl & Friction

  • Repeated credential prompts across pages increase security leakage risk.
  • Need for unified STS verification and client-side safe persistence.

Process Lifecycle

End-to-End Operational Workflow

Phase 1: Authenticate & Ingest

  • Connect: Admin inputs AWS Access Key, Secret Key, and Region.
  • Validate: Backend calls AWS STS to verify Account ID and Caller ARN.
  • Ingest: Parallel Boto3 calls retrieve CloudWatch metrics and EC2 inventory.

Phase 2: Analyze & Remediate

  • Security Audit: Evaluates inbound rules, unencrypted EBS, and IMDS posture.
  • Energy Curve: Evaluates server power consumption and carbon footprint.
  • Remediation: Emits ready-to-run AWS CLI commands for immediate execution.

Engineering Rigor

Debugging the 50% Flatline Bug ("Is this def wrong?")

The Root Cause

  • Backend Step Quantization: if cpu < 10: return 45. For idle EC2 instances (0.2-3% CPU), every hour was rounded to constant 45.
  • CSS Offset: .chart-bars had inset: 0 0 0 while grid lines had inset: 0 0 23px. 45% + 23px label placed every bar on the 50% grid line!

The Engineering Solution

  • Continuous Energy Curve: Implemented cubic power curve reflecting true server SPECpower energy consumption.
  • Synchronized CSS: Set inset: 0 0 23px and positioned labels outside flex height.
  • Added Metric Switch: Allowed operators to toggle between Efficiency and CloudWatch CPU %.
